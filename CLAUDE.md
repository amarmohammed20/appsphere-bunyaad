# CLAUDE.md

Read this before writing code. Every rule below is enforced — breaking one
fails the build, it does not get caught in review.

We standardise on Claude Code, so this is the only agent file. Skills,
subagents and hooks live in `.claude/`. If another tool is ever adopted, give
it a pointer to this file rather than a copy.

## Stack

Next.js 16.2 (App Router) · React 19.2 · TypeScript 5.9 strict · Tailwind 4 ·
Supabase · Zod 4 · pnpm 11.18

pnpm only. `npm install` and `yarn` are blocked.

## Before you say you are done

```bash
pnpm lint && pnpm type-check && pnpm format:check && pnpm build
```

All four must pass. `pnpm lint:fix` and `pnpm format` fix most failures.

## Structure

Feature-first. One folder per business domain, everything that domain needs
inside it. `src/features/users/` is the reference — copy its shape.

**[src/features/README.md](src/features/README.md) is the source of truth.**
Read it before adding a file. It covers the folder shape, where each kind of
code goes, and why.

The rules you will hit most:

- Features never import other features.
- Only `server/` may import the Supabase server client.
- Components call actions, never queries.
- `data/` holds compile-time literals only.
- No barrel files. Import the file you want.
- No top-level `helpers/` or `utils/`.

## Do not

- **Do not weaken a rule to make a command pass.** Not `eslint.config.mjs`,
  not `eslint.boundaries.mjs`, not `tsconfig.json`, not the workflows. If a
  rule seems wrong, say so and stop.
- **Do not use `eslint-disable` without a reason.** A bare one fails lint. The
  format is `-- why`, and the reason has to be real.
- **Do not add a dependency** without saying why a built-in will not do.
- **Do not commit a generated migration unread.** Diff it against the schema
  file it came from — the diff tool has captured default grants the schema
  never asked for.
- **Do not edit `src/components/ui/`** by hand. It is generated by shadcn.
- **Do not commit.** Supply the message and let a human run it.

## Warnings are not optional

Every rule is `error` on purpose, because warnings get ignored. If the command
exits non-zero, the work is not finished.

## When a rule blocks something legitimate

There is a sanctioned escape: one deliberate import, the rule disabled inline,
and a written reason. See the end of
[src/features/README.md](src/features/README.md). Use it rarely and visibly.
