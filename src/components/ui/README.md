# components/ui

Generated by shadcn. Add one with:

```bash
pnpm dlx shadcn@latest add <name>
```

Do not hand-edit for style — `add` regenerates the file and your change is
gone. The exceptions below are deliberate and must survive a regeneration, so
re-apply them if you ever run `add --overwrite`.

## Deliberate deviations from shadcn's defaults

| Change                                                                 | Where                      | Why                                                                                                                                |
| ---------------------------------------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `default` is `h-11` (44px), `lg` is `h-12`; `icon` and `icon-lg` match | `button.tsx`               | shadcn ships 32px, which suits dense desktop UI. Client apps get opened on phones. `sm`/`xs` are untouched for deliberate density. |
| Fixed `h-11` — this component has no size variants                     | `input.tsx`                | Same reason. There is no `cva` here, so the height is set once on the element.                                                     |
| `data-[size=default]` is `h-11`; `sm` left at `h-7`                    | `select.tsx`               | Same reason. There is no `lg` variant to raise.                                                                                    |
| `cursor-pointer`                                                       | `button.tsx`, `select.tsx` | shadcn leaves buttons on the default cursor.                                                                                       |

The size scale must stay ordered: `xs < sm < default < lg`. An earlier version
raised `default` past `lg`, which made `size="lg"` render _smaller_ than
`size="default"` — and the two hero buttons on the landing page were below the
44px minimum as a result.

## Lint

`import/order` is off for this folder in `eslint.config.mjs`, because `add`
regenerates these files and hand-ordering imports is churn that returns. A
**correctness** rule firing here means fixing the component, not widening the
exemption.

## Only what is used

Components are added when something needs them, not in anticipation. `sonner`,
`dialog`, `dropdown-menu`, `skeleton`, `card` and `separator` were all added
during the initial setup and removed the same day, unused. An unused component
reads as "we use this" and gets wired up without thought — the same reason an
unused Supabase browser client was deleted earlier.

`add` takes ten seconds.
